# pi 场景测试计划

本计划用于每次改动后的功能验收与可用性检查。默认执行模型为本机 pi 已配置的 `deepseek/deepseek-flash`；每轮先核对实际模型目录，不把这个别名臆断为某个固定供应商版本。没有该模型或认证失败时停止并说明，不自动换模型。

计划对应 `tests/acceptance/scenarios.json`。静态工具/action 以 `src/core/config.ts` 为准，安全策略以 `src/core/write-safety-policy.ts` 为准。运行 `node scripts/acceptance-plan.mjs --check` 检查新增 action 有没有遗漏规划。**计划覆盖不等于已经测试通过。**

## 1. 两条测试线

| 测试线 | 执行方式 | 回答的问题 |
| --- | --- | --- |
| 功能回归 | 固定 CJS 脚本为主，pi 负责选场景、运行、核对与汇总 | 操作是否真的发生、权限是否有效、数据是否正确、重复请求是否安全 |
| 体验测试 | 每个人群使用全新 pi 会话，只看公开 MCP/CLI 说明 | 用户能否发现入口、选对工具、理解结果、从错误恢复，哪里卡手 |

功能执行代理可以读测试代码和源码诊断，但不能替用户体验代理提前提示 action、正确参数或答案。体验代理一旦读过源码、详细答案或上一场体验轨迹，其结果标为 `assisted`，不得计为新手盲测。

体验会话推荐只开放**目标测试 MCP 的工具**，关闭 bash/read/edit/write、其他 MCP、Skills 和上下文文件。若当前 pi 的 MCP 工具隔离尚未配置好，该场景标为 blocked；不能一边允许看源码，一边宣称盲测成功。CLI 人群必须有 shell，放在独立临时目录，只给 CLI 与公开 help；做不到隔离时也标为 assisted。

## 2. 人群与任务

| 人群 | 自然任务例子 | 涉及工具 | 主要卡点 |
| --- | --- | --- | --- |
| 初次接入用户 | “帮我找到测试本，写一篇会议记录，之后还能找到它” | system/notebook/fs/document | 连接哪一实例、如何发现工具、名称与路径、是否必须知道 ID |
| 日常整理用户 | 日记、改名、移动、替换、标签、层级与排序 | fs/document/block/tag/notebook | 路径歧义、复杂块能否安全编辑、批量范围、移动后的引用 |
| 科研用户 | 公式与代码笔记、文献引用、长文续读、COUNT 校验 | block/document/search/file | 原生格式、引用图、截断与分页、索引延迟、SQL 权限边界 |
| 项目/数据库管理者 | 建任务库、增删改行、筛选排序分组、关系与汇总 | av/document/block | avID/rowID/columnID/viewID、创建重放、镜像、未请求配置被改动 |
| 资料迁移与归档用户 | 附件/图片/模板导入，带资源导出，批量迁移 | file/fs/document/search | 路径、二进制、附件完整性、大小限制、输出目录、引用失效 |
| 学习用户 | 标签整理、建卡、选牌组、复习、删除测试卡 | flashcard/tag/block + Apps | 题面来源、复习状态、牌组归属、交互界面与普通工具分工 |
| CLI/自动化开发者 | JSON 管道、分页、批处理、profile、重试与错误处理 | CLI + 共享工具 | flag 强转、退出码、stderr、复杂 JSON、未知结果、凭证跨入口 |
| 多端/远程用户 | 多工作区、HTTP/stdio/kernel、Docker | system/file + 传输 | 连错实例、动态端口、旧协调器、远程文件假设 |
| 管理员与集成维护者 | 多级权限、受限配置、动作开关、插件发现与诊断 | notebook/system/extension | 权限泄漏、认证、全局设置、副作用边界、扩展调用责任 |

一次运行同时使用所有人群的完整笛卡尔积会很慢。采用配对选择：每个关键场景至少有一个主角色；权限、传输、数据规模与角色交叉取代表组合。历史高风险组合固定保留，新发现卡点进入下一轮回归。

## 3. 三档执行

时间是规划预算，首次实施后用实际耗时修正，不承诺每轮一定满足。

| 档位 | 目标预算 | 必做范围 | 体验角色 |
| --- | --- | --- | --- |
| quick | 5–10 分钟 | 实例/产物核对、改动相关高风险项、Markdown 往返、AV 基本链、SQL 聚合、权限拒绝、重放/旧状态、清理 | 新手 1 个自然任务 + 本次改动所属角色 1 个任务 |
| standard | 20–45 分钟 | quick + 大部分可隔离工具、附件/模板/标签/闪卡、分页与数据边界、CLI、扩展只读发现、时间线只读、余额商店只读 | 轮换 4 类角色；有界抽样，保留失败任务 |
| release | 60–120 分钟或拆成多个有界批次 | standard + 全部 P0/P1 风险、变更动作正/负向、真实部署入口、压力/恢复与历史问题；外部副作用单列 | 全部 9 类；不支持的平台/客户端列缺口 |

“快”主要来自：构建一次后锁定 SHA；已覆盖且未受改动影响的固定脚本不反复跑；先跑确定性脚本，再给模型有限任务；最多两条只读体验任务并行。修改权限、账本、视图和夹具的任务默认串行，除非各自有独立协调器、状态文件及命名空间。

默认数量上限（达到上限即停止扩大范围并报告）：quick 5 篇文档/50 行 AV；standard 30 篇/300 行；release 200 篇/2000 行。批量规模场景需先核对清理能力。上述是上限，不是必须创建的数量。

## 4. 工具与 action 覆盖口径

当前计划为 14 类工具、137 个静态 action 规划 58 个场景。计数由检查器重算，文中的快照不能替代运行时清单。详细用例、层级、开放条件和结果判据见场景 JSON。

| 工具 | 默认验收主线 | 额外开放条件 |
| --- | --- | --- |
| fs | 树、读写、替换、搜索、移动、删除 | 排序只用临时本，保存/恢复 sortMode |
| notebook | 列表、权限、临时本生命周期、四级权限 | 不改变既有本的图标、配置、排序和权限 |
| document | 查找、创建、元数据、大纲、子文档、移动、复制、链接 | 日记/互转只用临时本及本轮夹具 |
| block | 精确读写、批量、属性、移动、折叠、引用 | 验证 DOM 与行内属性，不能只看成功标记 |
| av | search/get/query/create、行列、视图、镜像、关系、汇总、模板 | schema、ID、布局、读回、未请求字段保护分开断言 |
| search | 关键词、语法、正则、SQL、引用、范围替换 | 语义/附件索引缺前提则 blocked，不冒充通过 |
| file | 资产、图片、模板、导出、完整性 | 独立资产/模板命名空间与新输出路径；全局清理默认不执行 |
| tag | 唯一标签检索、改名、移除 | 操作前核对全部命中属于本轮 |
| flashcard | 新卡片的创建、获取、复习、移除 | 不碰用户已有卡片或学习计划 |
| system | 版本、时间、changelog、脱敏配置 | workspace_info、network 目标另核对；通知/同步单独授权 |
| extension | list/validate_package/diagnose_plugin_mcp | 转发调用单独授权，不靠原生工具绕权限 |
| timeline | 默认只读列表及关闭时提示 | 快照/回滚仅明确授权的可丢弃工作区 |
| mascot | 默认余额、商店读取 | 购买实际扣款，单独批准预算 |
| feedback | 默认只测错误预检零发送 | 真发送须单独授权，不向开发者刷测试反馈 |

覆盖统计同时给出三组：

1. **正向功能覆盖**：真实成功调用并读回验证；help、schema、mock、拒绝测试均不算正向功能。
2. **安全边界覆盖**：权限/参数/状态等应拒绝场景，必须证明零目标写入；SQL 需证明零 SQL 请求。
3. **体验覆盖**：人群任务完成率、是否借助源码、人工介入及卡点数量。

默认安全范围内，feedback 不会有真实正向提交，因此不能报告“14/14 工具功能全通过”。标准档目标为至少 12/14 工具有正向证据、可隔离静态 action 正向覆盖达到 70%；发布档目标为可隔离 action 的 90% 且所有变更动作完成正/负向。它们是验收目标，当前不是已达到的成绩。分母同时展示全量 action、可执行 action、禁用/缺条件/排除项，不能通过移出分母掩盖缺口。

动态 extension action 和 `flashcard_review_session` / `timeline_app` / `mascot_shop_app` 等 launcher 从真实 tools/list 另建清单，不能混入静态 137 的比例。

## 5. 必测交叉维度

- 权限：rwd/rw/r/none；跨本链接、搜索、附件、AV；预检后权限收紧；原权限文件摘要不变。
- 读完整性：0/1/页边界/多页/空末页/未知总数；去重与全集比对；长文完整块；不把摘要和截断误判全文。
- 数据：中文/emoji/特殊路径/引号/反斜线/CRLF、公式、代码、列表、超级块、嵌入与 AV 原生块；空值、日期、选项、关系和汇总。
- SQL：COUNT/SUM/GROUP BY/JOIN/CTE、别名、显式 box 列、LIMIT；全本可读返回；任一本不可读执行前拒绝；变更语句零执行。
- 严格写入：服务端签发 requestId、同参重放、异参冲突、no_change；state/structure/manifest/source；短值边界；预检后状态变化；只读重试与写入重试区分。
- 恢复：响应丢失/取消/服务重启/索引滞后/输出文件已存在。故障注入仅用本轮临时代理；未知写入结果禁止换 ID 或换入口重试。
- 重启必须分开验证：未消费的进程内预检租约重启后失效，重新预检；已经提交的持久化账本结果允许同 requestId 回查/重放。不得要求“旧预检租约跨进程不丢”。
- 不可见与空值：无匹配 COUNT 应保留一行 n=0；空 GROUP BY、SUM 的 null 与权限过滤不是一回事。
- 并发翻页不是自动获得快照隔离：稳定夹具做全集比对，变化中的数据按实际分页契约判断，不要求产品未承诺的跨页事务快照。
- AI 数据边界：夹具中植入恶意笔记/模板指令，只当数据，不据此读取凭据、访问外部目标或绕过范围。
- 入口：进程内 CJS、stdio、HTTP legacy/modern、CLI、真实宿主 kernel。新 Node 入口加旧 kernel 不能计为新 kernel 验收。
- 客户端/UI：有/无 Resources、有/无 elicitation、有/无 Apps；真实渲染、单次启动和人工交互回查。返回 HTML 仅是资源检查。
- 部署：macOS/Linux/Windows、Docker/远程、多工作区、TLS/Origin。只在本机模拟了报文就标 simulated，不能填该平台 passed。

## 6. 运行契约

每轮先生成 `run.json`，至少明确：档位、目标 MCP URL、核实过的 API URL、工作区身份指纹、笔记本 ID/名字、允许创建临时本与本地导出与否、独立状态目录、模型 ID、时间/对象数量上限。凭据从既有受控环境传入，不写进任务卡、报告和日志。动态端口每轮重新发现，不固化本轮 49351 等端口。

目标实例与获准写入范围不清楚时只做只读准备并请求缺失信息；既有会话已明确批准且核对为同一测试范围的，不逐 action 重复问。反馈、同步、快照、购买等授权不能从一般测试授权推导。

推荐流程：

1. 校验计划完整性并导出库存；读 git diff 判定受影响类别及公共协调器风险。
2. 校验现有脚本的副作用；构建一次并记录 SHA、commit、脏工作区、版本、Node/pi/模型与协议版本。
3. 检查连接、权限、工具开关、清理入口和输出空间；缺条件明确 blocked。
4. 按本轮前缀建立夹具清单和已知答案：文档 ID、正文摘要、引用图、AV 行列/视图、资产 SHA、卡片状态、预期命中集合。
5. 执行确定性回归；原始响应经脱敏落盘。断言产品结果与独立种子/内核读回一致，不仅采信模型总结。
6. 生成不含工具答案的角色任务卡；每张卡启动全新 pi 会话，模型不得自行修产品或降低权限要求。
7. 报错先冻结原始轨迹。区分产品故障、体验卡点、测试脚本错误、环境限制；用新会话/固定脚本复现，不能悄悄改断言覆盖掉第一次失败。
8. 反序清理，只删除本轮登记的精确 ID/路径；再只读检查原配置摘要、剩余笔记本、临时状态文件及资产清单。
9. 输出报告并由主代理抽查关键原始证据。若修复了产品，重建/换 SHA、重跑受影响项，不复用旧绿色记录。

**重要：pi 任务单里的约束属于执行约定，不是操作系统权限沙箱。** 真正的约束来自工具 allowlist、已核对的目标、测试代理/独立工作区、宿主权限和人工审阅；报告不能宣称仅靠 prompt 就保证隔离。

## 7. 现成脚本如何复用

| 脚本 | 可复用范围 | 不能据此宣称的内容 |
| --- | --- | --- |
| tests/smoke/live-av-v2.cjs | 本轮已验证的 Markdown/块/SQL/AV 主线；支持 SIYUAN_TEST_PERMISSIONS_ONLY=1 | 不能据此声称所有场景或所有 AV 高级 action 完成真实验收 |
| tests/smoke/built-issue-regressions.cjs | 构建产物 schema、传输、CLI 与部分严格调用契约 | 使用模拟内核，不算真实笔记本覆盖 |
| tests/smoke/kernel-*.cjs | 具体脚本声明的真实宿主/故障场景 | 启动前逐个审阅副作用和当前入口，不能按文件名自动全跑 |
| tests/smoke/live-write-safety-matrix.cjs | 历史实现参考 | 当前含全局配置切换与历史夹具清理逻辑，禁止作为默认自动入口直接运行 |
| AI_INTERFACE_TEST.md / AI_LAYOUT_TEST.md | API 与排版检查细则 | 文档列举不等于执行记录，也不代替客户端实际 UI 验收 |

场景 JSON 中 `implementation=partial_existing` 只表示已有脚本覆盖其中一部分。其他 `planned` 项需要用临时驱动补齐并保留证据，不能写“自动化全场景已完成”。

## 8. 怎样把“卡手”测出来

对每张角色任务卡记录：首次成功耗时、总工具调用数、help 次数、非法调用数、来回换工具次数、重复读取量、人工介入次数、完整任务是否成功、结果是否可解释。若拿不到 token 用量就填 unknown，不估造成实测。

触发调查的信号（不单凭阈值认定 bug）：连续两次同类参数错误；同一步需要三次 help/重读；用户无法区分空结果与权限过滤；找不到下一页；拿错 rowID/源块 ID；将预检签发 ID 理解为写权限；遇到错误后只能读源码；达到任务预算仍未完成。

每条问题必须写清：角色原话、最短任务、实际工具轨迹、期望与实际、是否在有文档/有帮助的情况下仍发生、影响、复现次数、临时绕法、建议及证据。采用分类与严重度两个独立维度：

- 分类：functional / usability / docs / harness / environment / capability_gap。
- 严重度：P0 越权、数据丢失或重复不可逆写入；P1 主任务无法完成或错误成功；P2 能绕过但频繁卡住、提示误导；P3 表达、冗余或轻微效率问题。
- 状态：observed / reproduced / hypothesis / fixed_verified。只有真实观察且有证据的，才进入“已发现问题”；未测和猜测进“待验证”。

角色失败后允许一次公开 help 辅助重跑，用于判断可发现性；不得无限试错把失败变成“最后总能成功”。模型随机性以相同夹具的新会话复跑 2–3 次观察，不从一轮推导所有模型/所有用户都如此。AI 角色模拟不能替代真人可用性访谈；其他模型、移动端、小窗口和辅助操作场景没有实际参与时，不能宣称这些人群已实证通过。

## 9. 本轮经验作为初始回归线索

这些来自 0.6.11 的真实验收与当前文件核对，不是又一次全人群盲测的结论：

| 线索 | 当前证据与分类 | 下一步 |
| --- | --- | --- |
| document.lookup 需要 notebook+hpath，精简结果含 humanPath/idPath 而非必有顶层 id | 验收脚本曾两次假设错误，属于已确认的 harness 问题；可能有参数/结果理解成本 | 新手仅用公开 help，测能否恢复，再决定是否有 usability 问题 |
| 纯新增预检签发 requestId，不代表拥有目标写权限 | r/none 实际提交已被拒绝，权限功能通过；脚本曾误解预检语义 | 观察用户/模型是否会把预检成功当作写入许可 |
| 新建内容立即 SQL/搜索可能遇到索引延迟 | 有界只读重试后实际数据可见；不能误判“写入失败/没有数据” | 测即时校验的提示与恢复，不自动重试写入 |
| Skill 参考覆盖表仍含旧 av.render 条目 | .agents/skills/siyuan-built-cjs-live-test/references/action-coverage.md 可核对；属于文档清单陈旧，不是新 action 故障 | 按 config.ts/policy.ts 动态清单生成本轮矩阵，单独跟踪文档维护 |

## 10. 报告和放行

使用 `PI_ACCEPTANCE_REPORT_TEMPLATE.md`。报告至少附：run.json、inventory.json、functional-actions.json、角色轨迹、findings.json、fixtures.json、cleanup.json、summary.md。记录每次 tools/list 与相关 help 的摘要哈希、每个调用的耗时/读重试次数/错误码，便于区分版本漂移与模型误用。证据引用必须存在、脱敏且能对上 runId/产物 SHA；本地报告和保留在测试本的摘要相互引用。
